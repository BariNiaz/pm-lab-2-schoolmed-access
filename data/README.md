# Данные проекта

Здесь лежат данные, с которыми работает проект. Реестр источников с описанием и оценкой каждого набора: [sources.md](sources.md).

## Структура

| Папка | Что лежит | В репозитории? |
|---|---|---|
| `raw/` | Данные в том виде, в каком их скачали. Не редактируем вручную. | Нет, только `.gitkeep`. Их можно скачать заново |
| `manual/` | Небольшие таблицы, собранные вручную из публикаций (например, население по районам). У каждой строки — год и ссылка на источник | Да |
| `processed/` | Очищенные данные, готовые для анализа (результат ноутбука 02) | Да, если файл меньше 10 МБ |
| `sources.md` | Реестр источников данных | Да |

Почему сырые данные не хранятся в Git: они большие, быстро устаревают и всегда восстанавливаются из источника. Зато способ их получения должен быть описан так, чтобы любой участник группы мог его повторить.

## Как получить данные

Пространственные слои скачивает `notebooks/01_data_collection.ipynb` из OpenStreetMap. Второй источник — CSV «Список поликлиник» с портала открытых данных Республики Башкортостан (DS-03), его нужно положить в `data/raw/clinics_source.csv` до запуска ноутбука.

**Вариант 1 — Google Colab (основной).**

1. Создайте общую папку группы на Google Диске с тем же именем, что у репозитория (`pm-lab-2-schoolmed-access`), остальные участники добавляют на неё ярлык в «Мой диск» (приложение Б к ЛР 2, шаг 2). Загрузите туда `data/manual/` из репозитория.
2. Откройте `notebooks/01_data_collection.ipynb` в Colab через **Файл → Открыть блокнот → GitHub**.
3. Впишите имя папки в `PROJECT_FOLDER` и выберите **Среда выполнения → Выполнить все**.
4. Ноутбук скачает слои в `data/raw/` на Диске; в конце он запишет журнал загрузки `_download_log.json` с датой и числом объектов.

**Вариант 2 — локально.**

1. Установите зависимости: `pip install -r requirements.txt`.
2. Запустите `notebooks/01_data_collection.ipynb` из папки `notebooks/` (Jupyter или VS Code).
3. Файлы появятся в `data/raw/` репозитория.

Скачивание проверено 15.11.2026: граница Уфы, районы, 163 школы и 251 медицинский объект из OSM. Повторный запуск обновляет данные; дату загрузки фиксируйте в отчёте о качестве.
