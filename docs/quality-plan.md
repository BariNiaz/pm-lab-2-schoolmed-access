# План управления качеством

Версия 1.0 · Дата: 21.11.2026 · Ответственный за качество: Тимур Зайнуллин

План опирается на нефункциональные требования из [requirements.md](requirements.md) (NFR-01…NFR-05), критерии приёмки историй и правила [definition-of-done.md](definition-of-done.md).

## 1. Что для нас качество

Заказчику важны три вещи: карта должна **быстро открываться и быть понятной** (NFR-01, NFR-02, NFR-05), расчёт доступности должен быть **воспроизводимым** (NFR-04), а данные — **достоверными и свежими**, иначе выводы о районах будут неверными.

Для команды качество — это ещё и предсказуемость процесса: каждый PR проходит ревью, автопроверки зелёные, ошибки находятся до слияния, а не после.

## 3. Стратегия тестирования

| Уровень | Что проверяем | Инструмент | Автоматически? | Где результат |
|---|---|---|---|---|
| Проверка данных | Структура слоёв: CRS, геометрия, дубликаты, границы города, минимальное число объектов | `scripts/validate_data.py` | Да, в CI | Лог CI / `data/validation.json` |
| Модульные тесты | Функции расчёта: расстояния, доли, перепроецирование, ближайшая поликлиника | `pytest`, `tests/` | Да, в CI | Лог CI |
| Приёмка историй | Критерии «Дано / Когда / Тогда» каждой истории | Ревью и обзор спринта | Нет, владелец продукта | Комментарий в задаче |
| Проверка выводов | Цифры в отчёте совпадают с выводом ноутбука, формулировки привязаны к данным | Второй участник прогоняет ноутбук | Нет | Комментарий к PR / ретро |

**Что не тестируем и почему:** ноутбуки целиком в CI не запускаются — им нужны данные из интернета и Google Диска, проверка стала бы медленной и нестабильной. Вместо этого расчётные функции вынесены в `src/geo_utils.py`, а тесты проверяют их; ноутбук только вызывает функции. Визуальную часть карты (NFR-03, совместимость с браузерами) проверяем вручную в Chrome и Firefox.

## 4. Чек-лист ревью Pull Request

**Для любого PR**
- [ ] PR связан с задачей (`Closes #N`), ветка названа по правилам
- [ ] Автопроверка `ci / quality` зелёная
- [ ] Нет пустых разделов и пометок TODO

**Код и ноутбуки**
- [ ] У новой расчётной функции есть тест, который проверяет известный ответ, а не повторяет код
- [ ] Ноутбуки сохранены без вывода ячеек, расчёты в метрической проекции (EPSG:32640)

**Данные**
- [ ] `scripts/validate_data.py` проходит, `data/validation.json` обновлён
- [ ] Новые фильтры данных объяснены в `docs/data-quality.md%%

**Документы**
- [ ] Цифры в документе совпадают с выводом ноутбука
- [ ] Выводы сформулированы «по данным OSM», с ограничениями, а не как абсолютный факт
- [ ] Использование ИИ записано в `docs/ai-usage.md%%

## 5. Качество в Definition of Done

В [definition-of-done.md](definition-of-done.md) добавлены пункты:

- автопроверка зелёная и тесты проходят;
- у новой расчётной функции есть тест с известным ответом;
- проверка данных проходит, `data/validation.json` обновлён;
- в документе есть абзац с ограничениями и ссылкой на источник данных.
